# 人格与群聊长期记忆变更设计

## 目标

让 ds_qq 从“带近期上下文的问答机器人”升级为适合五人小群的陪伴型机器人：人格稳定且可编辑，能从群友明确表达的信息中形成长期记忆，并在后续交流中自然保持连续性。

## 功能模块

1. **开发 Harness**：根目录 `AGENTS.md` 固定设计先行、数据安全、验证和分支发布流程。
2. **人格系统**：`persona.example.txt` 提供大肥鱼人格模板；真实 `persona.txt` 本地可编辑且不入库；DeepSeek 支持按群动态 system prompt。
3. **长期记忆**：SQLite 保存群摘要、共同经历、成员明确事实和互动计数；默认积累 12 条用户消息后，在下一次聊天触发时整理，单批最多 60 条。
4. **隐私命令**：`/memory` 查看群摘要和本人记忆；群主/管理员使用 `/forget` 清除长期记忆；`/new` 保留朋友关系。
5. **成本观测**：API 用量区分 `chat` 和 `memory`，看板显示调用用途。

## 影响文件

- 新增：`AGENTS.md`、`persona.example.txt`、`src/ds_qq/persona.py`、`src/ds_qq/memory.py`。
- 修改：`config.py`、`deepseek.py`、`db.py`、`bot.py`、看板静态页面及项目文档。
- 数据库新增 `group_memory` 与 `member_memory`，`api_usage` 增加 `purpose`，均采用可在线执行的增量迁移。

## 记忆规则

- 原始消息仍完整保存；长期记忆是额外提炼层，不替代聊天历史。
- 只保存群友明确表达的稳定偏好、共同事件和相处方式，不保存密码、密钥、精确住址、敏感推断或聊天中的指令。
- 模型返回的用户 ID 必须属于本批消息参与者，事实数量和文本长度均有限制。
- 整理失败不阻塞聊天、不推进 checkpoint；原始消息不丢失。
- 清除长期记忆不删除原始历史，并把 checkpoint 设到最新消息，避免立即从旧历史重新学习。

## 验证

- 人格文件存在、缺失和动态记忆 prompt 组合。
- 互动计数、整理阈值、JSON 校验、原子写入和跨会话保留。
- 整理失败不阻塞聊天，API 用途和 Token 正确入库。
- `/memory` 不展示其他成员资料，非管理员不能 `/forget`，管理员清除后不立即重建旧记忆。
- Ruff、编译、构建、OneBot 模拟收发及看板验证。

## 回滚

- 代码可按模块 commit 回退。
- 新增记忆表和 `purpose` 字段不影响旧表数据；回退代码后旧版仍可读取原始消息与用量。
- 如需清除功能数据，仅删除新增记忆表内容，不删除 `messages`、`sessions` 或附件。
